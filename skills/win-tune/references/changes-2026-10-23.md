# 2026-10-23 关闭自动锁屏 + 显示器 15 分钟黑屏

> 承接 `changes-2026-10-20.md`。那一轮解决的是「合盖 / 待机别断任务」，
> 这一轮解决的是「别自动锁屏，但屏幕可以黑」。

工作机：同一台笔记本（`GetSystemPowerStatus` → `BatteryFlag=1` 表示有电池，
`ACLineStatus=1` 当时接着电源）。当前电源方案 = **高性能** `8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c`，
另有 **平衡** `381b4222-f694-41f0-9685-ff5bb260df2e`，共 2 个方案。

用户原话：
- 「请把我的电脑调整成不自动锁屏，我需要锁屏的话会手动锁屏幕」
- 「另外如果 15 分钟不动电脑的话，屏幕就可以黑屏」

---

## 一、先把「谁在锁屏」查清楚

锁屏有四条独立路径，逐条排掉之后只剩一条：

| 可能原因 | 位置 | 实测 | 结论 |
|---|---|---|---|
| 屏保带「恢复时显示登录屏幕」 | HKCU `Control Panel\Desktop` | `ScreenSaveActive=0`、`ScreenSaveTimeOut=0`、`ScreenSaverIsSecure=0` | 早已关，不是它 |
| 组策略强制闲置锁屏 | HKLM `Policies\System\InactivityTimeoutSecs` | 键不存在 | 不是它 |
| 动态锁（蓝牙手机离开） | HKLM `Winlogon\EnableGoodbye` | 键不存在（默认关） | 不是它 |
| **唤醒时需要密码** | 电源设置 `CONSOLELOCK` | **AC=1 / DC=1** | **就是它** |

`CONSOLELOCK` 的逻辑：屏幕黑屏后系统进入「已锁定待机」状态，回来时按这个值决定要不要
弹登录界面。它是**隐藏**电源设置，设置页里藏在「屏幕保护程序设置 → 更改电源设置 →
唤醒时需要密码」，默认是「是」，所以屏幕一黑就等于自动上锁。

## 四、代价（写在这里，免得以后当成 bug）

`CONSOLELOCK=0` 的含义是：**机器仍然是「没锁」的状态**，只是屏幕黑了。
任何人碰到键盘鼠标都能直接进桌面，不需要密码。

这与用户「需要锁屏我自己手动锁」的用法一致，但必须明确交代：

- 离开时间较长 → `Win + L`（或 `Ctrl + Alt + Del` → 锁定）；
- 想恢复成「黑屏即锁」→ 把 `config/baseline.json` 的 `power.consolelock` 改回 `1`，
  跑 `apply --power-nosleep --yes`，或者直接用备份目录里的 `rollback.ps1`。

## 五、这一轮踩到的坑（已固化成代码）

| 现象 | 真相 |
|---|---|
| `powercfg /SETACVALUEINDEX` 返回 `rc=0`，但注册表里读不到 | **rc=0 只代表命令被接受**，不代表值落盘。必须回头用 `/qh` 读「当前交流/直流电源设置索引」才算数 |
| 用 `winreg` 在 `PowerSchemes\<方案>\<组>\0e796bdb-...` 找不到 CONSOLELOCK，误判成「没写进去」 | CONSOLELOCK 带 **SECURITYDESCRIPTOR** 属性，值不在 PowerSchemes 树里（两个方案整棵树都搜不到），存在 SECURITY 库。普通管理员读不到 → 只能解析 `powercfg /qh` |
| `powercfg /q` 完全看不到这个设置 | 它是**隐藏**设置，必须 `/qh` |
| `powercfg /qh <方案> 7516b95f-f776-4464-8c99-403798f61111` 返回 19 字节的用法提示 | 子组只能用**别名** `SUB_VIDEO` / `SUB_NONE`，不认组 GUID。`_scheme_vals()` 读注册表才用 GUID，两条路别混 |
| 改完只有当前方案生效，切到「平衡」又锁屏了 | 设置是**按方案**存的。`apply` 一律遍历 `all_schemes()` |
| `wmic path Win32_Battery` 报 `WinError 5` | `wmic.exe` 在 Program Blacklist 里。判有没有电池改用 ctypes 调 `kernel32.GetSystemPowerStatus`，看 `BatteryFlag != 128` |
