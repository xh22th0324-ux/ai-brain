# 双 AI 互批研讨 · 完整实战案例

> 本文件是 S3 的实证附件。案例来源：2026-09 一次真实的歌词打磨，创作方 × 批评方往返 **4 轮**，
> 最终批评方明确写出「可定稿」，再由真人终裁 2 处分歧后落定。全程可复制、可复现。

---

## 一、案例概览

| 项 | 内容 |
|---|---|
| 作品 | 一首国风流行歌（拟古诗，化用大量李白名句） |
| 创作方 | AI-1（负责写、改、逐条回应） |
| 批评方 | AI-2（人格设定：**毒舌批评家**，只挑错） |
| 真人 | 用户（终裁分歧，一票否决） |
| 轮次 | 4 轮（送审 → 批 6 条 → 修订 v2 → 批 4 条 → 终稿 v3 → 终审打回 2 处 → 修正 → 「可定稿」） |
| 产出 | 研讨纪要（过程证据链） + 终稿 + 分歧裁决记录（真人签字项） |
| 收敛信号 | 批评方连续挑不出结构性硬伤，明确写出**「可定稿」**三字 |

## 二、完整轮次时间线

```
【第 1 轮】
创作方送审：创作背景 + 歌词全文 + 约束条件 + 第1轮任务
      ↓
批评方：问题清单 6 条（三段式，全部可落地硬伤，无一句空泛评价）
      ↓
【第 2 轮】
创作方：逐条回应（接受 / 部分接受 / 反驳，每条给理由）+ 修订版 v2 全文
 + 明确标出「待真人终裁」的分歧项（自己不敢拍板的两处）
 + 第2轮任务（只针对新文本批，不许重复展开已标待裁项）
      ↓
批评方：问题清单 4 条（全部针对 v2 新增/改动处，未触碰待裁项）
      ↓
【第 3 轮 · 终稿轮】
创作方：逐条回应 + 终稿 v3 全文 + 终审任务（只做两件事，不许再给新改法）
      ↓
批评方：终稿硬伤扫描 2 条 + 最终分歧清单 4 条
      ↓
【第 4 轮 · 收尾轮】
创作方：接受 2 条硬伤，给出修正句，其余维持 v3
 + 任务（只回答一个问题：是否可定稿）
      ↓
批评方：**「可定稿」** + 最终分歧清单 2 条
      ↓
【真人终裁】
逐条裁决 → 写入「分歧裁决记录」→ 落定终稿
```

## 三、送审包五件套（每轮必附 —— 这是防跑偏的核心）

创作方每次送审，必须附齐这五样。缺任何一样，批评方都会开始自由发挥。

### ① 创作背景

```
这首歌《XXX》由我（创作方）执笔，词作者署名"XXX"（辑改名句）。
主旨：在当下经济萧条、普通人生活承压的背景下，借古人的洒脱豪放，劝人活得超脱不羁。
发布平台：抖音竖屏 MV；演唱：AI 虚拟歌手（女声，带戏腔）主唱。
用户本人最喜欢的一句是"……"。
```

> **最后一句至关重要**：提前声明真人的偏好句，批评方才知道哪些不能随便动。

### ② 歌词全文（带段落标注）

### ③ 约束条件 ← **整套流程的灵魂**

```
1. 所有古人原诗句（……）为定稿核心资产，不可替换，只能调整其前后衔接。
2. 全篇押韵骨架为言前辙（-an/-ian/-uan），引诗处保留原韵不算病。
3. 总时长目标 3 分钟左右（100 BPM），超长会被砍。
4. 已经过两轮人工修改，用户认可现有结构（……），大改结构需给出压倒性理由。
```

四条约束各有作用：

| 约束 | 拦住什么 |
|---|---|
| 不可替换的核心资产 | 防止 AI「顺手优化」掉整首歌的记忆锚点 |
| 韵脚骨架 | 给批评方一把**可量化的尺子**（否则批评全凭感觉） |
| 时长 + BPM | 把「字数和唱得下」变成硬指标 |
| **结构锁定 + 压倒性理由** | 最关键 —— 防止每轮推翻重来，永不收敛 |

### ④ 本轮任务（明确批评的靶心和数量下限）

```
请以批评家身份给出至少 5 个具体问题（原句/问题/改法 三段式），重点盯：
唱感口型（女声戏腔）、句子长短是否能唱、意象是否俗套、
古今两条线的缝合是否生硬、抖音听众 15 秒内是否有记忆点。
```

## 四、批评方硬约束（照抄给 AI-2）

```
你是这首歌的批评家，任务是挑错，不许夸。
每条问题必须写成三段式，缺一段不算：

【原句】引原文
【问题】具体错在哪 —— 必须落到可验证的点：韵脚辙口、字数节奏、
        典故出处、语体是否统一、听感（开口音/闭口音/齿音）
【改法】给出替换句，并逐条说明为什么更好

硬性要求：
- 至少 N 个问题，全为可落地硬伤，禁止「不错」「挺好」这类评价
- 每条改法要给替换文本，不能只说"建议优化"
- 不许提空泛的美学意见（如"可以更有画面感"），要说清是哪一句、错在哪、怎么改
```

**终稿轮追加规则**（防止无限循环）：

```
只做两件事：
1. 对全文做最后扫描：若仍有"唱不动/破韵/硬伤"级别的问题，列出（三段式）；
   若没有，直接写「可定稿」。
2. 给出最终分歧清单，每条一句话。
不要再提新的改法方案，不要扩写。
```

## 五、创作方回应规则（照抄给 AI-1）

```
逐条回应批评，每条必须归入三类之一：
- 接受 → 直接改，说明采纳理由
- 部分接受 → 接受哪部分、不接受哪部分、为什么
- 反驳 → 必须给出比对方更强的理由

反驳不是面子问题，是质量控制环节。
```

### 实录里的三条高质量反驳（值得记住的范式）

**反驳 1 · 覆盖面判断错误**

> 批评方建议把「KPI」换成「工单」，理由是韵脚和共情面。
> 创作方反驳：**工单是工厂/售后语境，写字楼白领反而没有工单，覆盖面比你想的窄。**
> 改用「加班」——全民痛点，同样收言前辙。

**反驳 2 · 典故张冠李戴（批评方自己犯的错）**

> 批评方给出衔接句「醉里偶题纨扇」。
> 创作方反驳：**「纨扇」是班婕妤《怨歌行》的弃妇意象，安在李白身上是新的张冠李戴。**

**反驳 3 · 语体断裂**

> 批评方建议改「屏间休晒体面，杯前莫念从前」。
> 创作方反驳：**文言过头 —— 前一句还在"闹钟/地铁/加班"的现代白话里，突然"屏间""杯前"会违和。**

> **这三条是整套流程最值钱的地方**：对抗性辩论能抓出单个 AI 抓不到的错误 ——
> 覆盖面偏差、典故误用、语体断裂。单 AI 自查几乎必然放过这类问题。

### 不许越权改真人定稿

批评方会本能地想"优化"掉真人的个人风格。规矩是：

> **真人亲手改定的用词，AI 只能标注建议，不得擅自替换。**
> 创作方把它列为「待真人终裁」项，连同两版一并提交。

实录中真人保留下来的两处（AI 都判为"有瑕疵"）：

- 一句被指**典故张冠李戴 + 破韵**，但真人偏爱 → 最终**弃用**（真人也可能采纳批评）
- 一句「五更残梦／油腻中年」被指**冒犯性标签 + 齿音闭口音**，但真人自嘲梗优先 → 最终**保留 A 版**

> 两种结果都出现过。**关键不是真人一定对，而是决定权必须在真人手里。**

## 六、真人终裁记录（模板）

```
分歧① ……… → 定 B 版
  终稿采用：……
  （弃 A 版"……" —— 理由，你选择让位于……）

分歧② ……… → 保 A 版
  终稿采用：……
  （弃 B 版…… —— 你的……优先，研讨意见记录在案，录音时注意……）

分歧③（知会项）……：未提异议，保留研讨版定稿。
```

> 写法要点：**每条都要写"弃用哪版 + 为什么"**。
> 这不是形式主义 —— 它是将来回看时唯一能解释"为什么这版长这样"的东西。

## 八、自动化：三条技术路线（实测结论）

**现状（2026-09 实测）：真正的自动化直连尚未落地，目前靠人工在两侧搬运。**

技术上可行，有三条路：

| 方案 | 做法 | 前提 | 稳定性 |
|---|---|---|---|
| **A. API 直连**（推荐） | 把流程固化成脚本：起草 → 调接口评审 → 回应改稿 → 再审，N 轮后按预定验收标准终裁 | 一方的 API Key | 最稳、可复现，每轮成本几分钱 |
| **B. 浏览器自动化** | 脚本在网页版里自动打字、读回复、再回复 | 先手工登录一次 | 遇验证码 / 改版 / 限流会中断 |
| **C. 本地脚本当裁判** | 两个 Key 都备上，本地跑对辩，产出 txt，全程不经第三方环境 | 两个 Key | 数据不出本机 |

### 关键提醒：API 里的是「裸模型」

> **API 里的模型不带技能、文件和工作目录。**
> 纯歌词文字研讨完全胜任；
> 但「读改 txt、落盘、生成 Word、做校验」这些能力，裸接口不自带。

所以如果要保住全流程（研讨 → 落盘 → 生成交付文档），**需要一个带文件能力的 Agent 当主持方**，另一方用裸 API 调用即可。

### 人工环节不要全砍

> **两轮 AI 容易互相迁就，或改着改着漂移。**
> 推荐配置：**自动研讨 N 轮 + 自动产出「推荐成稿 + 分歧记录」→ 真人花十秒扫一眼确认。**
> 信任规则的话，也可以约定好标准后完全自动落盘 —— 但「分歧记录」这一步别省。
