# 歌词大师一点通

**一句话**：从一个念头开始，到一条被人看见的成片 —— 中间每一步都有人替你把着关。

**这条线管到底：从词的第一笔，到片子的最后一帧。** 词是主角，曲子、画面、字幕、成片都是为了让你的字被人听见、被人看见。

---

## 上手之前，先花一分钟看这里

**这是一个「边聊边写」的向导，不是一篇读完就完的长文档。**

怎么走：

1. 先扫一遍下面的「全流程概览」，对整条线有个印象（3 分钟）
2. 从 **L1** 开始往下走，**每到岔路口都要停下来让你选**，不许替你拍板
3. 你选了哪条，就只讲哪条；没选的那些一个字都不铺
4. 每走完一步，明确告诉你「现在在哪、下一步是什么、还剩几步」

**为什么这么做**：写词有六个真正的分叉点，每个岔路只对特定情况适用。一次性把全部信息铺出来，等于让人在噪声里找信号。

**主 Agent 请守这几条**：

- 每步开头报一次进度：**「当前步骤 Lx／11」**
- 选择题一律走 AskUserQuestion，2~4 个选项，**把首选放第一位并标「推荐」**
- 用户选定后只展开那一支，**别顺手把落选的分支也念一遍**
- **不得替用户定稿** —— 真人拥有终裁权，这是流程的硬约束

## 全流程概览

```
 ── 词（这是主体）─────────────────────────────
 L1 选题定位        ← 决定「有没有人点开」
      ↓
 L2 曲式骨架        ← 决定「记不记得住」
      ↓
 L3 韵脚与节奏      ← 决定「唱不唱得出」
      ↓
 L4 出稿 ──────────┐
      ↓            │
 L5 双 AI 互批研讨 ─┘  ← 循环 3~4 轮，批评方写「可定稿」，真人终裁
      ↓
 L6 定稿与留证      ← 决定「权利是不是你的」
      ↓
 ── 落地（词从这里开始离开你的手）─────────────
 L7 定稿的去向      ← 交给谁听、卖给谁用、还是先放着
      ↓
 L8 词入声          ← 让字从嘴里出来：曲子怎么出、唱序怎么记
      ↓
 L9 词入画          ← 把句子翻成镜头：意象怎么落成画面
      ↓
 L10 词入轴         ← 让字被看见：字幕怎么呈现
      ↓
 L11 词成片         ← 见人：合成、发布、资产登记
```

**L1~L3 是设计，L4~L5 是生产，L6~L7 是兑现，L8~L11 是落地。** 跳过前三步直接写词，是绝大多数歌词「平庸且没法救」的根因。

## 三条硬原则（整套流程的地基）

### ① 词必须人写 —— 这不只是创作观，是法律问题

**AI 生成的曲在多数平台无法主张著作权。歌词是你唯一能落到「人类独创性」上的抓手。**

手稿、改稿记录、带时间的创作笔记 —— 是你将来一切权利主张的凭据。L6 会讲怎么归档。

创作层面同理：AI 写词的通病是意象堆砌、陈词滥调、一股说不清的「AI 味」。人写的词才有具体的生活质感。

> 用 AI 出草稿可以，但**你必须逐句改写**，且改写幅度要够大。纯 AI 生成的词在权利主张上等于裸奔。

### ② 一句只干一件事

**叙事句不抒情，抒情句不叙事，金句句只负责被记住。**

三者混在一句里的结果，通常是三件事都没干成。写完之后逐句标注「这句在干什么」，标不出来的就是废话，删。

### ③ 决定权必须在真人手里

AI 可以写、可以批、可以反驳，但**不许擅自改真人亲手定过的用词**。

配合这条的规矩：AI 只能把这类改动列为「待真人终裁」项，连同两版一并提交，研讨全程不碰。

> 实战中出现过两种截然相反的结局 —— 同一批待裁项里，真人一处采纳了批评、一处保留了原版。
> **关键不是真人一定对，而是决定权必须在真人手里。**

**→ 进入 L1**

## L1 选题定位

**目标**：定一个「观众一听就想点开」的题。

**核心公式**：**人人都知道，但没人这么唱过。**

选熟悉的题材不是因为偷懒，是因为**认知成本为零**。观众看到「李白」「李清照」「兰亭」就知道是谁，这一秒省下来的注意力，全部归你的内容。

### 五类高转化题材

| 类型 | 例子 | 为什么好用 |
|---|---|---|
| **课本必背篇目** | 《静夜思》《滕王阁序》选段 | 全民记忆，零认知成本，自带「爷青回」情绪 |
| **国民级名句** | 「人生若只如初见」 | 已是被验证过的情绪符号 |
| **历史人物反差面** | 李清照的晚年、李白的失意 | 越熟悉的人，反差越有杀伤力 |
| **特定人群共鸣** | 打工人、异乡人、中年人 | 精准，转发率高 |
| **节气时令** | 立秋、中秋、年关 | 有天然的时间流量窗口 |

### 题材 × 难度速查（选题阶段就避开后面的坑）

| 题材类型 | 词作难度 | 素材压力 | 上手建议 |
|---|---|---|---|
| 单人静态抒情（一位古人、一种情绪） | 低 | 低 | **首选**，新手从这类起 |
| 名篇化用（引原诗 + 现代段落缝合） | 中 | 低 | 有原诗撑着，是**性价比最高**的一类 |
| 群体情绪共鸣（打工人 / 中年） | 中 | 中 | 需要真实的生活细节，否则容易空 |
| 叙事型人物小传（讲完一生） | 高 | 高 | 需要 3~4 段主歌，容易超长 |
| 多人物 / 对话体 / 打斗场景 | 极高 | 极高 | **不碰** —— 词难写，且做成 MV 后崩坏率翻倍 |

### 系列化：别东做一首西做一首

按人物人生弧线做系列（少女 → 思妇 → 国破），**同一形象串一生**，让观众追更。

单首是运气，系列才是资产。

### 决策点

> 用 AskUserQuestion 问：**这首写什么题？**
> - **A. 名篇化用（推荐）** — 引一首人人皆知的古诗，用现代段落缝合，讲它背后的人生 B 面
> - **B. 原创命题** — 你自己定主题（某类人的处境、某段情绪），从零写
> - **C. 客户命题** — 已有人给了主题（企业曲、景区曲、寿宴曲、纪念曲）

**分支要点**：

- **A 名篇化用**：先定「引哪几句」——这几句是**不可替换的核心资产**，后面 L5 研讨时必须写进约束条件。→ **进 L2**
- **B 原创命题**：先写一句话主旨（「这首歌想让谁在什么时刻觉得被说中了」），写不出来就是还没想清楚，别往下走。→ **进 L2**
- **C 客户命题**：先问清四件事 —— 给谁听、什么场合放、有没有必须出现的词、交付日期。**没有这四项就别开工**，改了八版才对上的成本远高于前期的十分钟。→ **进 L2**

### 文案钩子公式（写完之后配文案用）

```
世人只知「A 面印象」的 X，
可谁懂她写下「最痛一句」时，背后的人生 B 面？
```

**→ 进入 L2**

## L2 曲式骨架

**目标**：在写词之前，先定「这首歌长什么形状」。

**先搭骨架再填肉。** 直接从头写到尾，十有八九写出一个「主歌冗长、副歌平庸、到桥段已经没话可说」的东西。

### 短视频时代的钩子经济学

**前 15 秒决定完播率，完播率决定一切。**

传统流行歌把副歌放在 40~60 秒处 —— 那是电台和专辑时代的逻辑，听众没有快进键。
短视频平台的逻辑相反：**用户手指一划就走了，所以副歌的核心句必须前置。**

| 场景 | 结构 |
|---|---|
| 传统发行（音乐平台听歌） | 主歌先入，副歌在 40~60 秒 |
| **短视频 / MV（推荐）** | **副歌核心句前置到 0:00~0:15**，再进主歌 |

### 三种结构模板

**模板 A · 短视频标准（推荐）**
```
副歌核心句（0:00~0:15，先声夺人）
  → 主歌 A1
  → 预副歌
  → 副歌（完整）
  → 主歌 A2（换角度，不重复 A1）
  → 副歌 ×2
```

**模板 B · 标准流行**
```
主歌 A1 → 预副歌 → 副歌
  → 主歌 A2 → 副歌
  → 桥段 → 副歌 ×2
```

**模板 C · 叙事民谣**
```
主歌 A1 → 主歌 A2 → 副歌
  → 主歌 A3 → 副歌 → 副歌
```

### 段落规格（照着填，别硬凑）

| 段落 | 行数 | 每行字数 | 干什么 |
|---|---|---|---|
| **主歌** | 4~8 行 | 7~12 字 | 铺场景、讲事实、给细节 |
| **预副歌** | 2~4 行 | 6~10 字 | 蓄力，把情绪往上推一格 |
| **副歌** | 4~6 行 | **5~10 字** | 情绪爆发 + 至少一句钩子 |
| **桥段** | 2~4 行 | 7~12 字 | 换一个视角或时空，制造转折 |

**副歌的字数必须比主歌短。** 这是最容易违反的一条 —— 主歌句子长、副歌句子也长，唱起来就是一片糊。**副歌是给嗓子发力的地方，不是给字数的地方。**

### 时长换算（用来预判会不会超长）

按 100 BPM / 4/4 拍：

| 项 | 值 |
|---|---|
| 1 小节 | 2.4 秒 |
| 1 个乐句（4 小节） | ≈9.6 秒 |
| 3 分钟总长 | ≈180 秒 |
| 扣掉前奏/间奏/尾奏（约 30 秒） | 实际唱段 ≈150 秒 |
| 折算乐句数 | **≈15~16 个乐句** |
| **折算唱词总量** | **约 120~200 字** |

> **写完先数字数。** 超过 250 字的，基本都要砍 —— 砍不动的结果就是作曲环节被迫砍你的词，
> 而那是在最不该动结构的时候动结构。

### 决策点

> 用 AskUserQuestion 问：**用哪种曲式？**
> - **A. 短视频标准（推荐）** — 副歌核心句前置，前 15 秒抓人；用于抖音/视频号/小红书分发
> - **B. 标准流行** — 主歌先入，情绪渐进；用于音乐平台发行、单曲循环向
> - **C. 叙事民谣** — 三段主歌连铺故事；用于人物小传、长故事题材

**选定后立刻做一件事**：把结构写成一个**空槽模板**（如「副歌核心句[4行] → 主歌A1[6行] → …」），
标好每段行数上限，再往槽里填。**填不进去的字，就地删。**

**→ 进入 L3**

## L3 韵脚与节奏

**目标**：给词装上「唱得出、听不清」的技术底座。

**这一步是新手和熟手的分水岭。** 词意再好，韵脚乱了、字数崩了、齿音堆在一起，唱出来就是一团噪音。

### 十三辙速查（北方话押韵的标准系统）

| 辙 | 韵母 | 听感 | 适合 |
|---|---|---|---|
| **发花** | a / ia / ua | 明亮、开阔 | 副歌、呼喊感 |
| **梭波** | o / e / uo | 半开、平实 | 主歌、叙述 |
| **乜斜** | ie / üe | 窄、轻 | 过渡句 |
| **一七** | i / ü / er（含 zhi chi shi ri zi ci si） | 细、闭口 | 主歌、低回、内心戏 |
| **姑苏** | u | 闷、收 | 主歌、压抑感 |
| **怀来** | ai / uai | 开阔、上扬 | 中段、期待感 |
| **灰堆** | ei / ui | 半闭、内收 | 主歌、惆怅 |
| **遥条** | ao / iao | 响亮、开朗 | 副歌、豪迈 |
| **由求** | ou / iu | 半闭、沉吟 | 主歌、感伤 |
| **言前** | an / ian / uan / üan | 鼻音、开阔 | **万能辙**，主副歌都能用 |
| **人辰** | en / in / un / ün | 鼻音、细 | 主歌、叙事 |
| **江阳** | ang / iang / uang | **最响亮、最开阔** | 副歌高潮、气势 |
| **中东** | eng / ing / ong / iong | 鼻音、浑厚 | 副歌、雄壮 |

> 完整表格与逐辙例词见 `references/lyric-craft.md`。

**选辙三原则**：

1. **副歌往上走** —— 副歌用开口大、响亮的辙（江阳 / 遥条 / 发花 / 中东），情绪才推得上去
2. **主歌往下沉** —— 主歌用内敛的辙（一七 / 姑苏 / 灰堆 / 由求），叙事才立得住
3. **别全篇一个辙** —— 主歌一副韵 + 副歌一主韵，是最稳妥的配置，层次自然拉开

### 换韵规则

| 规则 | 说明 |
|---|---|
| ✅ 主歌 / 副歌可以换辙 | 制造段落边界感，是最常见的做法 |
| ✅ 引古人原诗处，保留原韵不算破韵 | **必须在研讨时写进约束条件**，否则会被当成硬伤批 |
| ❌ 副歌内部不要换辙 | 副歌是记忆点，韵脚一乱，钩子就散了 |
| ❌ 同一段内不要来回换 | 除非刻意做情绪断裂，否则听起来像拼接 |

### 字数与乐句对齐（最容易被忽略的一步）

**一个乐句的字数，直接决定它能不能被唱出来。**

| 位置 | 建议字数 | 说明 |
|---|---|---|
| 主歌每行 | 7~12 字 | 叙事容量够，又不至于一口气唱不完 |
| 副歌每行 | **5~10 字** | 短，好记，好发力 |
| 钩子句 | **5~8 字** | 越短越容易被记住、被复述 |

- **同段内各行字数尽量整齐**，允许 ±2 字的浮动
- 字数差超过 4 字的相邻行，作曲时必然要删字或加字 —— **那是在最难改的地方改结构**
- 写完之后**把每行字数标在右边**，对着看，一眼就能发现哪个句子是异类

### 三个听感陷阱（唱出来才知道坏在哪）

| 陷阱 | 表现 | 怎么改 |
|---|---|---|
| **连续同音字** | 咬字含糊，像嘴里含着东西 | 拆开或换字（「四是四」类） |
| **齿音密集** | 喷麦、刺耳（z / c / s / zh / ch / sh / j / q / x） | 一句里齿音字不超过 2 个 |
| **闭口音连收** | 憋气、传不远（一七 / 姑苏 / 灰堆辙收尾） | 副歌句尾尽量落在开口音或鼻音上 |

### 另外两条硬规则

- **叠字句单独成行** —— AI 唱歌最容易吞叠字（「轻轻」「慢慢」连读就糊了）
- **避免生僻字** —— AI 咬字会崩，字幕也难做，观众还认不出

### 决策点

> 用 AskUserQuestion 问：**韵脚怎么安排？**
> - **A. 主副歌换辙（推荐）** — 主歌下沉辙 + 副歌响亮辙，层次最清楚
> - **B. 单辙到底** — 全篇一个辙，统一感最强，但容易单调、也容易硬凑
> - **C. 引诗保原韵** — 大段引用古诗词原文，韵脚跟随原诗，现代段落向它靠

**选定后立刻做一件事**：把韵脚骨架写成一行（如「主歌：言前辙 -an / 副歌：江阳辙 -ang」），
**这行字后面要原样写进 L5 的约束条件** —— 它是给批评方的一把可量化的尺子。

**→ 进入 L4**

---

## L4 出稿

**目标**：在骨架和韵脚都定好的前提下，拿到第一版完整词稿。

### 决策点

> 用 AskUserQuestion 问：**初稿从哪来？**
> - **A. 真人主笔（推荐）** — 你自己写，AI 只做打磨和挑错
> - **B. AI 出草稿 + 人工大幅改写** — 让 AI 按骨架填一版，你逐句重写
> - **C. 已有现成文本** — 古诗词原文、公版作品、客户给的文案

**分支要点**：

- **A 真人主笔**：照着 L2 的空槽模板和 L3 的韵脚骨架填。写不动的地方**先空着**，别硬凑 —— 空着的地方后面可以补，硬凑的句子会一直留在稿子里。→ **进 L5**
- **B AI 出草稿**：给 AI 的提示词必须包含**骨架槽位 + 韵脚辙口 + 字数上限**三项，否则它会写成一堆长度不一的漂亮废话。拿到草稿后**你必须逐句改写**（重点删附录 A 里的那些大词和套话），改完一样进 L5。**注意**：纯 AI 生成的词在权利主张上等于裸奔，改写幅度要够大。
- **C 现成文本**：
  - **古诗词、公版作品** — 可自由使用。但注意：**公版的是原文，不是别人对它的注解、白话译文、或改编版本**，那可能是别人的著作权
  - **他人现代词作** — 必须取得授权，否则侵权
  - **客户给的文案** — 默认版权归客户（除非另有约定），你只有署名权。签约时看清这一条

### 初稿自检（写完立刻过一遍）

```
[ ] 总字数在 120~200 区间吗？（超 250 要砍）
[ ] 副歌每行 ≤10 字吗？
[ ] 每行字数标注了吗？异类句子找出来了吗？
[ ] 韵脚骨架和 L3 定的一致吗？
[ ] 逐句标注过「这句在干什么」吗？标不出来的删了吗？
[ ] 叠字句单独成行了吗？
[ ] 齿音、闭口音结尾检查过了吗？
```

### 留证（立刻做，别拖）

**把这一版的原稿存一份，带时间戳。**

不是形式主义 —— 从第一版开始留档，你的改稿链条才是完整的。中途才开始留的存档，证明不了前面的创作过程。

归档内容：**手稿照片 / 文本原稿 / 带时间的创作笔记**。→ L6 会讲完整归档清单

**→ 进入 L5**

## L5 双 AI 互批研讨

**目标**：把一份「还行」的词，打磨到**双方都挑不出结构性毛病**。

> 以下机制来自一次**已跑通的完整实战**（4 轮收敛 + 真人终裁）。
> 完整实录、轮次时间线、高质量批评与反驳范例 → **`references/dual-ai-review-case.md`**

### 为什么需要「两个」AI

**一个 AI 自己改自己的稿，改不出东西。** 它会反复确认自己是对的。

**两个 AI 也不一定有用 —— 除非给它们对立的人格。** 不给角色设定，它们会互相吹捧，研讨沦为走过场。

| 角色 | 定位 | 硬性要求 |
|---|---|---|
| **AI-1 创作方** | 写、改 | 必须**逐条回应**批评：接受 / 部分接受 / **反驳**，每条给理由 |
| **AI-2 批评方** | 挑错 | 人格设定为**「毒舌批评家」**，只挑错，三段式，禁止空泛评价 |
| **真人** | 终裁 | 定稿权，一票通过或否决 |

### 决策点

> 用 AskUserQuestion 问：**互批怎么跑？**
> - **A. 标准 3~4 轮（推荐）** — 实战验证的收敛区间：批 6 条 → 修订 → 批 4 条 → 终稿 → 终审打回 → 修正 → 可定稿
> - **B. 快速 2 轮** — 赶时间、或对初稿已经很有信心
> - **C. 交给引擎跑** — 用技能自带的 `scripts/dual_ai_review.py`，全自动（两个 Key）或半自动（零 Key）。见下节

### 四轮循环（照抄执行）

```
【送审】AI-1 提交：创作背景 + 歌词全文 + 约束条件 + 本轮任务
        ↓
【批】  AI-2 出问题清单（三段式，至少 5 条）
        ↓
【回应】AI-1 逐条回应（接受/部分接受/反驳）+ 修订版全文 + 标出待真人终裁项
        ↓
【再审】AI-2 只批新增/改动处，不重复展开已标待裁项
        ↓
（循环 N 轮）
        ↓
【终稿轮】AI-2 只做两件事：列硬伤 或 写出「可定稿」；不许再给新改法
        ↓
【真人终裁】裁决分歧 → 写入「分歧裁决记录」
```

### ⭐ 送审包五件套 —— 缺一样，AI 就开始自由发挥

| 件 | 内容 | 作用 |
|---|---|---|
| ① 创作背景 | 主旨、发布平台、演唱者、**真人最喜欢的一句** | 提前声明偏好句，AI 才知道哪些不能动 |
| ② 歌词全文 | 带段落标注 + 每行字数 | 让批评方看得见节奏问题 |
| ③ **约束条件** | 核心资产不可替换 / 韵脚骨架 / 时长+BPM / 结构锁定 | **整套流程的灵魂**（见下） |
| ④ 本轮任务 | 指定靶心 + 问题数量下限 | 不让批评方想到哪批到哪 |
| ⑤ 上轮回应 | 第 2 轮起附上 | — |

**约束条件模板（照抄，四条都要写）**：

```
1. 所有古人原诗句（……）为定稿核心资产，不可替换，只能调整其前后衔接。
2. 全篇押韵骨架为言前辙（-an/-ian/-uan），引诗处保留原韵不算病。
3. 总时长目标 3 分钟左右（100 BPM），超长会被砍。
4. 已经过 N 轮人工修改，用户认可现有结构（……），大改结构需给出压倒性理由。
```

> 第 4 条最关键 —— **没有它，每轮都会被推翻重来，永远不收敛。**
> 第 2 条给批评方一把**可量化的尺子**，否则批评全凭感觉。

### 批评方硬约束（照抄给 AI-2）

```
你是这首歌的批评家，任务是挑错，不许夸。
每条问题必须写成三段式，缺一段不算：

【原句】引原文
【问题】具体错在哪 —— 必须落到可验证的点：韵脚辙口、字数节奏、
        典故出处、语体是否统一、听感（开口音/闭口音/齿音）
【改法】给出替换句，并逐条说明为什么更好

硬性要求：
- 至少 N 个问题，全为可落地硬伤，禁止「不错」「挺好」这类评价
- 每条改法要给替换文本，不能只说"建议优化"
- 不许提空泛的美学意见（如"可以更有画面感"），要说清是哪一句、错在哪、怎么改
```

**终稿轮追加规则**（防无限循环）：

```
只做两件事：
1. 全文最后扫描：仍有"唱不动/破韵/硬伤"级问题就列出；没有，直接写「可定稿」。
2. 给出最终分歧清单，每条一句话。
不要再提新的改法方案，不要扩写。
```

### ⭐ 创作方的**反驳权** —— 这是整套流程最值钱的地方

AI-1 不是照单全收。**反驳必须给理由**，因为对抗性辩论能抓出单 AI 抓不到的错：

| 实录中的反驳 | 抓出的错误类型 |
|---|---|
| 「工单是工厂/售后语境，写字楼白领反而没有工单，覆盖面比你想的窄」 | **覆盖面判断偏差** |
| 「『纨扇』是班婕妤《怨歌行》的弃妇意象，安在李白身上是新的张冠李戴」 | **批评方自己用错典故** |
| 「前一句还在闹钟/地铁的现代白话里，突然『屏间』『杯前』会违和」 | **语体断裂** |

> 单 AI 自查几乎必然放过这三类问题。**别把反驳当面子问题，它是质量控制环节。**

**创作方回应规则（照抄给 AI-1）**：

```
逐条回应批评，每条必须归入三类之一：
- 接受 → 直接改，说明采纳理由
- 部分接受 → 接受哪部分、不接受哪部分、为什么
- 反驳 → 必须给出比对方更强的理由
```

### ⭐ 不许越权改真人定稿

**真人亲手改定的用词，AI 只能标注建议，不得擅自替换。**

做法：AI-1 把它列为「**待真人终裁**」项，连同两版一并提交，研讨会全程不碰。

> 实录中真人保留下来的两处，AI 都判为"有瑕疵"（一处典故张冠李戴、一处用词带冒犯标签）。
> **关键不是真人一定对，而是决定权必须在真人手里。**

### 收敛判定

满足其一即停：

- 批评方明确写出 **「可定稿」** 三个字（**不是"感觉差不多了"**）
- 真人认为达标

> ⚠️ **警惕假收敛**：批评方只给两三条就写「可定稿」，说明它在放水。
> 自检办法 —— 看纪要里每轮的批评条数、反驳条数、采纳比例。条数骤降且无反驳，就是放水信号。

### 真人终裁记录（模板）

```
分歧① …… → 定 B 版
  终稿采用：……
  （弃 A 版"……" —— 理由，你选择让位于……）

分歧② …… → 保 A 版
  终稿采用：……
  （弃 B 版…… —— 你的……优先，研讨意见记录在案，录音时注意……）
```

> 每条都要写**「弃用哪版 + 为什么」** —— 这是将来唯一能解释"为什么这版长这样"的东西。

### 自动化：本技能自带引擎（`scripts/dual_ai_review.py`）

**不用自己搭。** 技能包里已经带了一个零依赖的研讨引擎，两条腿走路：

| 模式 | 需要什么 | 干什么 |
|---|---|---|
| **`auto` 全自动** | 两个 OpenAI 兼容接口的 Key | 起草 → 送审 → 回应改稿 → 复审，自动往返 N 轮，每轮落盘，批到「可定稿」为止 |
| **`manual` 半自动** | **什么都不用**（零 Key） | 引擎只负责生成每一轮的提示词文件，你复制到两个网页版 AI 里粘贴，把回复存回来 |

**没填 Key 时会自动降级到 manual**，不会报错卡住。

**用法（三步）**

```
1. 把 scripts/config.example.json 复制成 config.json，改 mode 和 task
2. 在技能目录下执行 python scripts/dual_ai_review.py
3. 去输出的目录里拿：每轮稿件 + 批评意见 + 研讨纪要 + 真人终裁记录空表
```

**配置要点**

- **两边必须用不同平台/不同模型**，否则会自我吹捧，研讨沦为走过场
- 创作方 `temperature` 调高（0.9~1.1），批评方调低（0.2~0.4）
- 常见平台的 `base_url` 速查写在 `config.json` 里（DeepSeek / 火山方舟 / 通义 / Kimi / 智谱 / 硅基流动 / Ollama / LM Studio）
- 引擎已内置：反驳权、三段式批评、收敛规则、待真人终裁标记、防覆盖存档

> ⚠️ **API 里的是「裸模型」——不带技能、文件和工作目录。**
> 纯歌词文字研讨完全胜任；但「读改 txt、落盘、生成 Word」这些能力裸接口不自带。
> 引擎用标准库自己做了落盘，所以这部分不依赖模型能力。

> ⚠️ **人工环节不要全砍。** 两轮 AI 容易互相迁就或改着改着漂移。
> 引擎的收敛信号是批评方白纸黑字的「**可定稿**」三个字。
> 但**最后一步必须由真人做**：把分歧项逐条裁定，填进「真人终裁记录」。这一步不能自动化。

### 另外两条路（引擎跑不通时的备选）

| 方案 | 做法 | 稳定性 |
|---|---|---|
| **B. 浏览器自动化** | 网页版里自动打字、读回复、再回复 | 遇验证码/改版/限流会中断；有账号风险 |
| **C. 手动搬运** | 两份提示词 + 两个网页 AI，人来当搬运工 | 最笨但永远能跑，引擎的 manual 模式已覆盖 |

### 工具

任何两个可对话的 AI 都行（豆包 / 千问 / Kimi / DeepSeek 任选其二）。

> **关键不是用哪家，而是让它们站在对立面 —— 且给真人留终裁权。**

**→ 进入 L6**

## L6 定稿与留证

**目标**：让「这首词是你写的」这件事，在将来能被证明。

### 归档清单（权利证据链）

```
✅ 歌词手稿 / 初稿 / 每次改稿（带时间戳）      ← L4 起就要存
✅ 带时间的创作笔记（灵感来源、为什么这么改）
✅ 研讨纪要（每轮稿件 + 批评意见 + 修改说明）
✅ 各轮版本全文（v1 / v2 / v3 / 定稿）
✅ 分歧裁决记录（真人签字项）
✅ 最终定稿（标注完成日期）
```

**存在本地，不要只留在某个平台的云端。** 平台的赔偿上限通常只是你付过的订阅费。

### 版权登记的三条实话

| 说法 | 实际情况 |
|---|---|
| 「区块链上链确权」 | ⚠️ **≠ 版权登记。** 上链只是带时间戳的数字存证，证明「某时刻你手里有这文件」，**不产生著作权、不能对抗第三方** |
| 「AI 作品不能登记」 | 部分对。纯 AI 生成的**曲**通常无法登记；**但歌词如果是人写的，它是可以主张著作权的** —— 关键看你能不能拿出创作过程证据（就是上面那份归档清单） |
| 官方登记去哪 | 中国版权保护中心（或各省版权局）。**词 + 曲可以分开登记，也可以作为音乐作品整体登记** |

### 决策点

> 用 AskUserQuestion 问：**要不要现在做版权登记？**
> - **A. 先归档，暂不登记（推荐）** — 词还没进商业环节，先把证据链做扎实；等有商业价值时再登记
> - **B. 立刻登记** — 词已确定要商业使用（接单交付、上架发行、授权第三方），**建议登记**
> - **C. 只要归档** — 个人娱乐、非商业用途，归档足够

**→ 进入 L7**

## L7 定稿的去向

**目标**：定稿之后，这首词去哪儿、能不能换钱。

**这一节只讲「词」这一个维度的变现**，不涉及歌的播放分成和 MV 分发。

### 四条路

| 路径 | 怎么换钱 | 现实量级 |
|---|---|---|
| **① 交给作曲环节** | 不直接换钱，但它是后面所有收入的前置 | 基础动作 |
| **② 认领词曲收益** | 词曲作者按比例分歌曲总收入 | **原唱版 16% / 翻唱版 35%**（长期被动） |
| **③ 出售词曲** | 平台上挂 demo，买家买断或授权 | 买断 3,000~50,000 / 授权演唱 1,000~8,000 |
| **④ 定制词单** | 按客户命题写词，按单收费 | **当月见现金，确定性最高** |

### ③ 与 ④ 的区别（决定你怎么报价）

- **出售词曲（③）是买家市场** —— 平台只提供撮合，不保证成交。挂上去卖不掉的 demo 是绝大多数
- **定制词单（④）是卖家市场** —— 客户命题、你交付、满意就打款。**不审版权来源，不看平台规则**

> 手上还没有作品集的时候，先走 ④ 攒案例，同时把 ③ 挂上去等机会。

### ② 认领词曲收益 —— 这一步别漏

**签约时必须把「作词」栏填成你自己。** 空着或填成工具名，等于主动放弃后面所有分成。

| 版本 | 词曲作者分成 |
|---|---|
| 原唱版本 | 歌曲总收入的 **16%** |
| **翻唱版本** | 歌曲总收入的 **35%** |

> 翻唱那份比原唱还高 —— 因为翻唱版通常没有原唱分成竞争。
> **只要你的词被人唱了、被人翻唱了，你就永远有一份钱。** 这是写词这件事最值钱的地方。

### 决策点

> 用 AskUserQuestion 问：**这首词准备怎么用？**
> - **A. 做成歌发行（推荐）** — 进作曲环节，走 ①②：认领词曲收益吃长尾
> - **B. 挂到词曲商城出售** — 走 ③：上传「音频+歌词」，建议勾选「更有利于成交」
> - **C. 接定制单** — 走 ④：先攒 3 首案例，再对外报价
> - **D. 先写完放着** — 只归档，将来再做

### 交付作曲环节时，要附什么

**别只丢一段文本。** 附上这三样，作曲环节会顺很多：

```
1. 歌词全文（带段落标注 + 每行字数）
2. 韵脚骨架（哪个辙、哪几行押）
3. 情绪与速度（参考 BPM、想要的感觉）
```

> 作曲方拿到这三样，才不会把你的词改得面目全非。

**→ 进入 L8**（从这里开始，你的词要变成声音了）

## L8 词入声：让字从嘴里出来

**目标**：把定稿的词，变成一首真能听的歌 —— 而**不是**一首「旋律好听、你的词被改得认不出来」的歌。

### 先交出去的三件套

进作曲环节之前，别只丢一段文本。附上这三样，对方才不会把你的词改得面目全非：

```
1. 歌词全文（带段落标注 + 每行字数）
2. 韵脚骨架（哪个辙、哪几行押）
3. 情绪与速度（参考 BPM、想要的感觉）
```

### 抽版：听的是「词有没有被吃掉」

同一首词抽 5 版挑 1 是常规操作。**但挑什么，大多数人挑错了** —— 他们在听旋律好不好。

**你的词才是不可替代的那部分。旋律可以换，字不能被吃掉。** 所以五版听完，只查三件事：

| 查什么 | 具体表现 | 后果 |
|---|---|---|
| **吃字** | 某句为了塞进旋律，被砍掉两三个字 | 意思断了，L1 定的钩子句可能直接没了 |
| **改序** | 段落顺序被调整（副歌提前、桥段挪后） | L2 定的结构白搭，情绪推不上去 |
| **重唱尾声** | 副歌末尾被重复一遍或改写 | **记下来** —— L10 做字幕全靠这个 |

> **把「实际唱序」当场记下来。** 不是记歌词稿的顺序，是记**耳朵听到的顺序**。这张纸在 L10 值很多时间。

### 演唱：音色是作品的身份证

- **自己的声音** → 最有辨识度，也最省事；但要接受它不够完美
- **AI 演唱** → 稳定、可重来；注意平台协议通常只许可「你自己的声音」
- **找人唱** → 效果上限最高，成本与沟通成本也最高

**一条红线**：不模仿真人歌手的音色。平台协议基本都不许可，且法律风险实打实。

### 决策点

> 用 AskUserQuestion 问：**这首歌的出声道怎么定？**
> - **A. AI 作曲 + AI 演唱（推荐首选）** — 快、便宜、可无限重抽；适合先跑通全流程
> - **B. AI 作曲 + 你自己唱** — 保住人声辨识度，需要一点录音条件
> - **C. 找人作曲 / 找人演唱** — 上限最高，周期与成本也最高

**→ 进入 L9**

## L9 词入画：把句子翻译成镜头

**目标**：把词里写的东西，变成看得见的画面。

**这一步是「词作者做 MV」和「剪辑师做 MV」最大的分野。** 剪辑师想的是「这段配什么转场」；词作者应该想的是——**我这句词里的那个东西，在画面上长什么样。**

### 核心工具：意象 → 镜头翻译表

写词时用的是意象，做片时要用的是镜头。中间这一步翻译，决定了片子是「有词的味道」还是「随便配了点好看的画面」。

| 词里出现的东西 | 画面怎么给 | 别怎么给 |
|---|---|---|
| **具体器物**（灯 / 舟 / 窗 / 杯） | 特写或近景，占画幅三分之一以上 | 远景里一个小点 —— 观众认不出 |
| **时间**（三更 / 暮色 / 立秋） | 用光线和天色说，一处道具佐证 | 打在字幕上写「三更」 |
| **情绪**（愁 / 念 / 悔） | 交给一个动作，或一个空镜承接 | 让人对着镜头做表情 |
| **人群**（世人 / 谁 / 他们） | 剪影、背影、只给局部 | 群演正脸 —— 出戏且崩脸 |

> **一句话原则**：**词里写具体的，画面就给具体的；词里写虚的，画面要给实的接住。**
> 反过来做（虚词配虚景），片子会飘；而且观众记不住任何一帧。

### 一个意象的三个档位

同一个意象，可以往三种方向翻。选哪档，取决于这首歌的调性：

| 档位 | 做法 | 适合 |
|---|---|---|
| **写实再现** | 真有那盏灯、那扇窗 | 叙事型、人物小传、纪实感 |
| **写意象征** | 用同类质感的东西替代（灯 → 一豆烛火） | 国风、拟古、抒情 |
| **抽象色块** | 只留色与光，不给具体物 | 氛围向、纯音乐感、诗词朗诵 |

**一部片子里不要三档混用。** 定了哪档就一路走到底 —— 混着来，观众会觉得画面在打架。

### 哪句配人像，哪句配空镜

**按词的情绪起伏排，不按技术方便排。**

| 词的位置 | 画面 | 为什么 |
|---|---|---|
| 主线叙事句 | 人像（对口型） | 有人称、有动作，需要一张脸 |
| 情绪爆发句 | 人像近景 | 情绪需要表情承接 |
| 铺陈 / 转场 | 空镜 | 给观众一口气，也给自己省钱 |
| 时间跳转处 | 空镜 | 用景别变化表示「换了个时空」 |

### 画面预算（先定，再动手）

**2 张立绘 + 4~6 条空镜**，是单角色、约三分钟片子的常规配置。

**先把数报出来再生成** —— 后面每一次生成都是钱，预算清楚的人才不会中途发现超支。

### 决策点

> 用 AskUserQuestion 问：**这首词的画面走哪一档？**
> - **A. 写意象征（推荐）** — 国风 / 拟古 / 抒情题的默认选择，意象清晰又留白
> - **B. 写实再现** — 叙事型题材，画面直接讲故事
> - **C. 抽象色块** — 诗词朗诵、氛围向；**成本最低**，且不需要人脸

**→ 进入 L10**

## L10 词入轴：让字被看见

**目标**：让观众在听到的同时**看见**你写的字。

**字幕不是附属品，是词的第二次生命。** 一首歌有人听不清唱什么，但字幕会替你说完。词作者在这一步的收益，比在其他任何一步都直接。

### 三种呈现形态

| 形态 | 做法 | 适合 | 工量 |
|---|---|---|---|
| **整句字幕** | 一段一行，整句上屏 | 叙事、长句为主 | 低 |
| **卡拉OK 逐字** | 唱到哪个字亮哪个字 | 副歌、钩子句 | 中 |
| **词卡** | 整句大字居中，画面让位给字 | 金句、题眼、开篇 | 低 |

**推荐组合**：主歌走整句，副歌切逐字，开篇与最核心那句做词卡。**同一首词里，字是主角的那几句要单独设计。**

### ⚠️ 唱序 ≠ 写序（最容易翻车的一条）

**AI 作曲经常会改写或重复尾声**（实测：尾声唱两遍、唱序与歌词稿不同）。

**字幕必须按 L8 记下的「实际唱序」拆条，不能照着歌词稿一行一行贴。**

贴错的后果不是难看，是**观众会以为你写错了词**。

### 可读性硬指标

| 项 | 下限 | 说明 |
|---|---|---|
| 字号 | 画面高度的 **1/12** 以上 | 手机小屏 + 老年观众，再小就白做 |
| 行宽 | 每行 **≤ 14 字** | 超过就要断行，否则扫读困难 |
| 对比 | 字与背景明暗差要够 | 画面亮处加描边或半透明底衬 |
| 出现时机 | 早于声音 **0.1~0.2 秒** | 眼睛比耳朵快，字晚到会让人「追不上」 |
| 停留 | 唱完后再留 **0.3 秒** | 立刻消失会显慌 |

### 决策点

> 用 AskUserQuestion 问：**字幕做成什么形态？**
> - **A. 混合式（推荐）** — 主歌整句 + 副歌逐字 + 金句词卡
> - **B. 全篇整句** — 最省工，画面最干净；适合氛围向
> - **C. 全篇逐字高亮** — 最抓人，也最费工；适合重点作品或要冲数据的曲子
> - **D. 不做字幕** — 纯音乐感；**但会丢掉一大批靠字幕听懂歌的观众**

**→ 进入 L11**

## L11 词成片：见人

**目标**：让这首词真的被人看见、听见 —— 而不是躺在你的文件夹里。

### 合成（动手做出来）

到这一步，手里应该已经有：**分好段的唱段视频 + 空镜 + 音频 + 字幕**。合成是力气活，不是创作活，按这个顺序走：

```
1. 建 9:16 竖屏工程
2. 音频轨铺一条完整的原曲（画面段全部静音 —— 歌声要一路连着）
3. 照 L9 的配画表把画面段摆进去
4. 字幕按 L8 记的实际唱序逐条校对
5. 头尾加上片名与账号名，并在片尾挂「内容由 AI 生成」声明
6. 输出 1080P / 30fps
```

> 各环节的平台参数、档位与成本，属于制作端的活儿，本技能不展开 —— 需要细参数时去问制作侧的工具或同行。**这里只保证：你的词在最后一步没有被做丢。**

### 发布：词作者自己该做的事

**这一步是很多人的断层。** 词写得好、片子也做出来了，结果发出去没人看 —— 问题通常不在作品，在这三样：

| 项 | 怎么做 |
|---|---|
| **标题** | 用 L1 的钩子公式反向回填：**「世人只知 A 面的 X，可谁懂 B 面？」** 别写成「原创古风歌曲分享」 |
| **封面** | 一帧最能代表主题的画面 + 一行 ≤8 字的题眼，不要堆字 |
| **文案** | 前两行决定展开率。**第一行给情绪，第二行给背景**，别一上来就报歌名 |

### 三条红线（发布前过一遍）

1. **「内容由 AI 生成」必须标** —— 法定强制，不是平台偏好。**主动声明不影响流量；不标会被判定并可能降权。**
2. **不翻唱别人的作品、不模仿真人歌手的音色** —— 前者侵权，后者平台协议基本都不许可。
3. **不批量上传雷同内容** —— 同一首歌的多个版本建议错开发。

### 决策点

> 用 AskUserQuestion 问：**这首词打算怎么见人？**
> - **A. 先发一条，看数据再加码（推荐）** — 单条打穿一个平台，成本最低
> - **B. 系列化发** — 按 L1 设计的人物弧线，同一形象连发多首，让观众追更
> - **C. 多平台同时铺** — 覆盖面大，但精力分散；建议错开时间发
> - **D. 先存档不发** — 攒够三首再一起发，作品集更像样

### 收尾：一个词作者的资产表

发完之后，把这首词的资产登记齐。**这是把「写了一首歌」变成「攒了一份资产」的分界线。**

```
✅ 词：定稿全文 + 各轮改稿 + 分歧裁决记录（L6 的归档）
✅ 曲：音频母带 + 实际唱序记录（L8）
✅ 片：成片文件 + 字幕文本 + 画面素材原图
✅ 数据：发布时间 / 平台 / 播放与互动（用来判断下一首往哪走）
✅ 署名：各平台「作词」栏都填了自己（L7 的 16% / 35% 靠它）
```

**→ 这条线走完了。** L6 的归档别漏，L5 的真人终裁表别空着。

## 附录 A · AI 味检测清单

**写完先自己过一遍。** 出现下列任一情况，就是 AI 味在冒头。

### 大词黑名单（出现即警惕）

```
岁月  时光  流年  青春  红尘  天涯  沧桑  远方  梦想  初心
心灵  灵魂  喧嚣  静好  温柔以待  人间值得  迷失  彷徨  迷茫
永不放弃  勇敢飞翔  照亮前方  心中那份  最深的眷恋
```

> **规则**：一首词里这类词**不超过 2 个**。它们不是不能用，是**不能连着用** —— 一旦成串出现，整首词就变成了背景音。

### 结构套话

| 症状 | 表现 |
|---|---|
| **排比成瘾** | 连用三个「不是……而是……」或三连排比 |
| **抽象配抽象** | 「让梦想照亮前方」—— 谁？照亮哪？全虚的 |
| **万能结尾** | 「这就是我们的青春」类，换任何主题都成立 |
| **意象乱飞** | 月 → 酒 → 风 → 雨，之间没有逻辑，只是好看 |
| **押韵押到死** | 每句都押、每句都工整，反而像机器（真人写词会有意破格） |
| **句句等长** | 全篇每行都是 7 字 —— 音乐性反而死了 |

### 一句话自测

> **把这首词读给你妈听，她能复述出其中的画面吗？**
>
> 复述不出画面，说明它只有情绪没有内容。

## 附录 D · 坑位速查

### 选题与结构

1. **一上来就写多人物、对话体、打斗场景** → 词难写且必超长，新手别碰
2. **跳过骨架直接从头写到尾** → 必然主歌冗长、副歌平庸、桥段没话说
3. **副歌句子和主歌一样长** → 唱起来一片糊，副歌要短
4. **总字数超 250** → 作曲环节被迫砍你的词，那是最不该动结构的时候

### 韵脚与节奏

5. **为押韵硬凑句子** → AI 味最大的来源，宁可破韵也别硬凑
6. **副歌内部换辙** → 记忆点散了，钩子失效
7. **齿音堆在一句里** → 喷麦刺耳，一句里齿音字别超 2 个
8. **副歌句尾连用闭口音** → 憋气传不远，句尾尽量落开口音或鼻音
9. **叠字不单独成行** → AI 唱歌会吞叠字
10. **用生僻字** → AI 咬字崩 + 字幕难做 + 观众认不出
11. **忘标每行字数** → 数不出节奏问题，到作曲环节才发现唱不下

### 研讨流程

12. **两个 AI 用同一个模型/同一平台** → 互相吹捧，研讨沦为走过场
13. **不给批评方人格设定** → 它只会说"不错""挺好"
14. **送审包缺「约束条件」** → 每轮都被推翻重来，永远不收敛
15. **约束条件里漏了第 4 条（结构锁定）** → 最常见的不收敛原因
16. **没有反驳权** → 创作方照单全收，批评方的错误也被采纳（实战中批评方自己会用错典故）
17. **允许 AI 改真人定过的词** → 你的个人风格被「优化」掉
18. **验收标准模糊** → 要能明确写出**「可定稿」三个字**才算收敛
19. **批评条数骤降还判定收敛** → 假收敛，批评方在放水

### 留证与合规

20. **中途才开始留档** → 证明不了前面的创作过程，从初稿就存
21. **只留云端不留本地** → 平台赔偿上限通常只是你付过的订阅费
22. **把「上链存证」当版权登记** → 上链不产生著作权、不能对抗第三方
23. **引他人现代词作不取得授权** → 侵权
24. **把公版的「注解/译文/改编版」当公版用** → 原文是公版，别人的注解可能不是
25. **签约时「作词」栏空着** → 等于放弃 16%/35% 的词曲分成
26. **接客户定制单却承诺「版权归你且独家」** → 看清合同，客户文案默认版权归客户

### 引擎与环境

27. **`config.json` 用记事本另存** → 会带 BOM，解析报错（引擎已兼容，但知道你遇到的是什么）
28. **本地回环请求被代理拦截** → 表现为 502，引擎已内置绕过
29. **API Key 写进要上传的技能包** → 泄露。Key 只放本地 `config.json`
30. **后台跑脚本秒挂无输出** → 前台重跑看真实报错

## 附录 E · 合规红线

| 红线 | 说明 |
|---|---|
| **公版作品可自由用** | 古诗词原文、超过保护期的作品。但**别人的注解、白话译文、改编版本不在其列** |
| **他人现代词作必须授权** | 未授权即侵权，且平台会追责 |
| **AI 生成内容须标识** | 上传音乐平台或发短视频时，需如实申报 AI 参与环节；短视频起始画面要有显著提示 |
| **不模仿真人歌手音色** | 平台协议通常只许可「你自己的声音」 |
| **接单只能承诺非独占** | 多数音乐平台协议已让平台持有永久、可转授权的使用权 —— 你卖不了排他性 |
| **歌词是你唯一的人类独创性抓手** | 手稿、改稿记录、时间线，务必本地归档 |

## 实战参考

**已验证案例**：一次国风拟古歌词的完整打磨 —— 创作方 × 批评方往返 **4 轮**收敛，真人终裁 2 处分歧后落定。

**完整实录**（含每轮送审包、6+4 条批评明细、3 条高质量反驳、终裁记录写法）→ **`references/dual-ai-review-case.md`**

**核心心得**：这套流程的壁垒不在「会用 AI」，而在两件事 ——

1. **把闸门设在机器不该拍的板上**（真人终裁、真人定稿不可越权改）
2. **逼出对抗性**（对立人格 + 反驳权 + 可量化的批评尺子）

> 一个 AI 写得快，两个对立的 AI 才写得好，**但只有真人知道这首词该长什么样**。
