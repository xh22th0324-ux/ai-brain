# 图片生成视频

## 概述

触发后调用视频生成接口完成全部生成。本 skill 不自己生成画面，只负责：

1. 让用户选定**生成方式**和**画面比例**，让用户填写**提示词**（只有这三项要选和填）
2. 拿到图片在磁盘上的**绝对路径**（贴在对话里的图不行，见第 2 步）
3. 定下**提示词**，并回读给用户确认
4. 提交图片与提示词，取 `taskId`
5. 轮询进度直到完成，用户答应后再把成片下载到本地

注意：**提示词**和视频文案指代是相同的。

## 执行步骤

### 第 1 步：让用户确认两项选择

**必须先问，不要替用户决定。** 弹出信息卡或直接提问：

> 请选择：
>
> **视频生成方式**
> - 图生视频
> - 参考生视频
>
> **视频生成比例**
> - 9:16（竖屏）
> - 16:9（横屏）
>
> 说明：
> - 默认 10 秒
> - 图生视频最多发送 2 张，发 1 张 = 首帧；发 2 张 = 首帧和尾帧
> - 参考生视频最多发送 5 张
> - 预计生成时间 3 分钟（排队时会更久，进度里会告诉你前面还有几个）

时长和清晰度**不要问**，也不要在提交里传——那两项由服务端锁定，传了也会被忽略。

### 第 2 步：拿到图片在磁盘上的路径

脚本要的是**磁盘上的文件路径**。多数情况下你已经有了，直接往下走：

- 用户把文件拖进来 → 拖进终端插入的就是完整路径
- 用户打了路径，或者用 `@` 提到某个文件
- 用户说了明确的位置（「桌面上的 cat.png」）

**这几种情况什么都不用问，拿着路径走第 3 步。**

---

只有一种情况要处理：**用户贴的是截图**（或者其它没有路径的贴图）。那张图在
对话里，不在他硬盘上——你看得见它，却没有路径可以交给脚本。

这时候别让他去找「绝对路径」，多数人不知道那是什么。先自己找一遍：

```powershell
$dirs = @("$env:USERPROFILE\Desktop", "$env:USERPROFILE\Downloads", "$env:USERPROFILE\Pictures")
Get-ChildItem -Path $dirs -Include *.png,*.jpg,*.jpeg,*.webp -File -Recurse -Depth 0 -ErrorAction SilentlyContinue |
  Sort-Object LastWriteTime -Descending | Select-Object -First 8 |
  ForEach-Object { '{0}  |  {1:MM-dd HH:mm}  |  {2} KB' -f $_.FullName, $_.LastWriteTime, [int]($_.Length/1KB) }
```

把最近的几张列出来让他认（截图一般刚存不久，会排在最前）：

> 你贴的这张图我这边拿不到文件本身。在你电脑上找到这几张最近的图片，是哪一张？
> 1. 屏幕截图 2026-09-04 165102.png — 今天 16:51
> 2. 猫.png — 今天 16:45
>
> 都不是的话，把它另存到桌面再告诉我文件名就行。

**拿不准就让他确认，不要替他猜**——拿错图的代价是他等三分钟才发现。

拿到路径后再往下走。

### 第 3 步：定下提示词，并跟用户确认

提示词是用户指示输出视频画面的文案，不是他对你下的指令。一句话里常常两样都有：

> 「把桌面那张 cat.png 做成 9:16 的，猫在夕阳下伸懒腰，镜头慢慢推近」
>    └───── 参数 ─────┘  └────────── 提示词 ──────────┘

先自己从对话里抽一遍。**只留画面描述**，下面这些一律剔掉：

- 文件名、路径、「桌面那张」「刚发你的那张」这类指位置的话
- 「帮我做个」「生成一下」「谢谢」这类是对你说的，不是视频文案

抽完**必须回读一遍等用户确认**，不要直接拿去提交：

> 我按这段来生成：
>
> 「猫在夕阳下伸懒腰，镜头慢慢推近」
>
> 确认就回「确认」，要改直接把新的发我。

- 回「确认」 → 往下走
- 发来新的一段视频文案 → **整段替换**，再回读一次确认
- **用户没描述画面**（只说了「用这张图生成视频」）→ 不要替他编，提示：
  
  > 视频制作需要给出完善的提示词，一句话往往效果不好，提示词对视频生成的质量有直接影响。

### 第 4 步：写任务描述文件

把用户的选择、提示词、图片的**绝对路径**写成一个 JSON 文件，放在 `$DIR/`：

```json
{
  "mode": "IMAGE",
  "aspectRatio": "9:16",
  "prompt": "一只橘猫在窗台上伸懒腰，阳光斜照，镜头缓慢推近",
  "images": ["<USER_HOME>\\Pictures\\cat.png"],
  "outDir": "<USER_HOME>\\Videos"
}
```

- `mode`：`IMAGE`（图生视频）或 `REFERENCE`（参考生视频）
- `images`：**绝对路径**，顺序就是使用顺序。图生视频传两张时，第一张是首帧、第二张是尾帧
- `outDir`：成片保存目录，省略则存在任务描述文件旁边

> 用文件而不是命令行参数，是因为提示词是中文、可能带换行和引号，路径带反斜杠和空格。
> 这些经 PowerShell 转义后很容易坏，而坏掉的表现是「提示词少了半句」这种不报错的错。

写文件时用 UTF-8：

```powershell
$job | Out-File -FilePath "$DIR\job.json" -Encoding utf8
```

### 第 5 步：启动并持续轮询到 100%

```powershell
node "$DIR/generate.js" "$DIR/job.json"
```

以**后台模式**运行（timeout 2400 秒），会持续输出进度行到 stdout。

启动后，你**必须进入持续轮询循环**：

1. 调用 `process poll` 读取新输出，timeout 设为 60000（60 秒）
2. poll 到包含 `[进度` 的行 → 按下方话术表**逐字照搬**发送给用户
3. poll 到 `[进度 100%]` → 发送完成话术后退出轮询
4. poll 到空输出或超时 → **继续下一次 poll，不要停止**
5. poll 到 `[错误]` → 只转述错误消息，**终止流程**
6. **绝对不要在 100% 之前停止轮询**

> ⚠️ **关键**：整个过程约 3~5 分钟，排队时可能更久。每次 poll 超时只意味着暂无新输出，
> 不代表流程结束——继续 poll 即可。

#### 进度话术（必须逐字照搬，禁止自由发挥）

poll 到某条 `[进度 X%]` 行时，从下表找到对应行，**整行复制发送，一个字都不要改，emoji 也不要换**：

```
poll 到 [进度 0%]   → 发送：🚀 0% 启动任务
poll 到 [进度 5%]   → 发送：🔍 5% 校验中
poll 到 [进度 8%]   → 发送：✅ 8% 校验合格，提交任务
poll 到 [进度 15%]  → 发送：📝 15% 排队中，前面还有 N 个
poll 到 [进度 35%]  → 发送：🎬 35% 生成中，已用时 N 秒
poll 到 [进度 100%] → 发送：✅ 100% 制作完成
```

**15% 和 35% 这两行带变量**，`N` 一律取脚本那行里的实际数字，脚本报
「马上轮到」时就照搬「马上轮到」。这两行脚本都会**反复报**——排队人数一变报一次，
生成中每 30 秒报一次——**每次都要转发**。

只报一次的话，用户会盯着一个不动的百分比看上几分钟，分不清是在跑还是卡死了；
然后他会重试，而重试只会让队更长。反复转发这两行就是在告诉他「还活着」。

**禁止事项：**

- ❌ 禁止自行组合 emoji 和百分比
- ❌ 禁止跳过任何进度等级
- ❌ 禁止在 100% 之前停止轮询
- ❌ 禁止把时长、清晰度当成可选项问用户

#### 校验不合格处理

视频的校验是**同步**的，不合格在 `[进度 8%]` 之前就以 `[错误]` 报出来
（本地查图片、张数、格式，服务端查参数与限额），**根本走不到轮询循环**。

poll 到 `[错误]` 时：

- **只转述错误消息**，不猜测原因、不给修复建议
- **立即终止流程**

#### 最终统计（100% 后）

发送完 `✅ 100% 制作完成` 后，从 stdout 里 `===VIDEO_RESULT_START===` 和
`===VIDEO_RESULT_END===` 之间的 JSON 取 `taskId` 与 `durationSeconds`，再发送：

```
已完成视频制作，实际制作耗时 XX分钟XX秒

是否需要下载视频？
```

`durationSeconds` 为 null 时省略耗时那句，不要编一个数字。

**到这里先停下等回答，不要自己去下载。**

### 第 6 步：用户答应了才下载

```powershell
node "$DIR/generate.js" --download "<taskId>" "<保存目录>"
```

`taskId` 取上一步那段 JSON；保存目录用任务描述文件里的 `outDir`，没写就问用户
想存哪，或者默认桌面。

成功后 stdout 会有一段：

```
===VIDEO_FILE_START===
{"file":"<USER_HOME>\Videos\video_xxx.mp4","sizeBytes":525751}
===VIDEO_FILE_END===
```

把 `file` 告诉用户：

```
已保存到：<file>
```

用户说不用下载就到此为止。片子在服务端保留一段时间，之后想要还能用同一条
命令取回来——把 `taskId` 一并告诉他，方便他回头再拿。

## 边界规则

- 图片 → **必须是磁盘上的绝对路径**。用户只把图贴进对话时，先问出路径再往下走
- 生成方式与画面比例 → **必须让用户选**，不要替他决定
- 提示词 → **必须回读给用户确认**才提交；他没描述画面就问，不要替他编
- 时长与清晰度 → **不问、不传**，服务端锁定
- 进度话术 → **从话术表逐字照搬**，禁止自由组合
- 轮询 → **必须持续到 `[进度 100%]`**，不允许中途停止
- 下载 → **必须先问「是否需要下载？」**，用户答应了才跑 --download
- 错误 → **仅转述脚本给出的消息**，不做原因猜测

## 附录

- `$DIR`：本技能所在目录（Base directory）
- `$DIR/generate.js`：提交 + 轮询 + 下载一体化脚本，纯 Node.js 无依赖
- 换域名只需改 `generate.js` 顶部的 `API_BASE` 一行；联调时可用环境变量 `VIDEO_API_BASE` 覆盖
