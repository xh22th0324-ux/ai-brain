# tools/ — 随包携带的小工具

这里放**拿来就能跑**的独立脚本，和另外两个目录有明确分工：

| 目录 | 是什么 | 谁会用 |
|---|---|---|
| `skills/` | 方法论：怎么做一件事的流程与判断标准 | AI 按流程干活 |
| `scripts/` | 本仓库自身的维护工具（导出技能、生成清单、密钥扫描） | 维护这个仓库的人 |
| `tools/` | 通用小工具：给定输入、产出结果，与仓库本身无关 | 任何需要这个功能的人 |

判断标准很简单：**删掉这个仓库，`tools/` 里的脚本照样有用。**

工具都是纯标准库实现，不需要 `pip install`：Python 工具 3.7+ 直接跑，
shell 工具是 POSIX sh（busybox ash 也能跑），Linux / NAS 端用。

## zip_each — 批量单独压缩

把目录下的**每个文件各自压成一个独立的压缩包**，原文件不动。

典型场景：一堆散文件要逐个发给别人、逐个上传，或者按文件单独归档。
需要一个总包时**不要**用它，`zip -r` 或 `scripts/make_zip.py` 更合适。

| 文件 | 用途 |
|---|---|
| `zip_each.py` | 主程序，Windows / Linux / macOS / NAS 同一份 |
| `zip_each.bat` | Windows 双击启动器：自动找 Python，跑完停住窗口 |

### 用法

```bash
python zip_each.py                        # 处理脚本所在目录
python zip_each.py D:\照片                 # 指定目录
python zip_each.py /data/new --out /data/packed
python zip_each.py --check                # 只做环境自检（在 NAS 上建议先跑）
python zip_each.py --dry-run              # 只预览会压哪些、跳过哪些
```

Windows 上把两个文件一起放进目标目录，**双击 `zip_each.bat`** 即可。
NAS / Linux 只有 `zip_each.py` 有用，`.bat` 可以忽略。

### 自动跳过规则

**已经压过的文件不会重复压。** 判定依据是目标包的时间戳：

| 情况 | 行为 |
|---|---|
| 目标包不存在 | 压缩 |
| 包存在，且**不比源文件旧** | **跳过** |
| 包存在，但源文件压完之后又被改过（包比源旧） | 重压，避免留下过期包 |
| 包存在但是 0 字节（上次中断的残留） | 补压 |
| 加了 `--overwrite` | 无条件全部重压 |

所以中断后直接重跑即可，已完成的部分会跳过。判定留了 2 秒容差，
兼容 FAT/exFAT 的 2 秒时间精度和 SMB 的秒级取整。

> 若源文件的修改时间在未来（相机时钟错、跨时区拷贝），它每轮都会被判为"比包新"
> 而反复重压。结果不会错，只是白费时间，用 `touch` 校正源文件时间即可。

### 其它行为

- **只处理第一层文件**，不递归子目录
- 目录里已有的 `.zip/.rar/.7z` 默认跳过（避免 `a.zip.zip`），`--include-archives` 可关闭
- 隐藏文件、`Thumbs.db`、`desktop.ini` 跳过
- 已经是压缩格式的（mp4/jpg/mp3/docx…）走**仅存储**模式，不浪费 CPU
- 先写 `.part` 再原子改名，断电或 Ctrl+C 不会留下"看起来完整"的坏包
- 命名默认替换扩展名（`a.mp4 → a.zip`）；去掉扩展名后重名的，改追加模式
  （`photo.jpg → photo.jpg.zip`）以免互相覆盖
- 网络路径（SMB/CIFS/NFS）自动把并发从 8 降到 4

### 在 NAS 上

```bash
python3 zip_each.py --check          # 先自检：Python 版本、文件系统编码、可用工具
python3 zip_each.py /data/new
```

没有 `python3` 时（iStoreOS 精简固件）：`opkg install python3-light`，
或在 Debian / python 容器里跑：

```bash
docker run --rm -v /data:/data python:3.12-slim python /data/new/zip_each.py /data/new
```

`--format rar` 在 iStoreOS 上基本用不了 —— 官方 rarlinux 是 glibc 二进制，
而 iStoreOS 是 musl 环境。用 `--format zip`，或进 Debian 容器。

## hdd_sleep — 外挂硬盘休眠：体检、验证、实现

三个脚本，**按顺序用**。核心结论先说：**这块盘的 USB 桥接只认 `hdparm -y`，
`hdparm -S` 和 `hd-idle` 都是假成功。**

| 文件 | 用途 |
|---|---|
| `hdd_sleep_diag.sh` | 体检：能不能睡、谁在偷写、强制睡后多久被吵醒 |
| `verify_sleep.sh` | **验证**：把时间缩短到 2 分钟，看它到底会不会睡 |
| `cron_sleep.sh` | 实现：自己计时，到点调 `hdparm -y` |

### 先讲结论：为什么标准方案会失效

网上（包括 OpenWrt 官方文档）给的两条路，在这类 USB 外置盘上**都可能无效**：

| 方案 | 机制 | 常见失败方式 |
|---|---|---|
| `hdparm -S` | 把空闲计时器写进盘（ATA `IDLE`） | **假成功**：返回 0，实际没设。SCSI 协议里没有对应命令，桥接直接吞掉 |
| `hd-idle` | 守护进程计时，到点发 spindown-now | 进程在跑、参数正确、盘也空闲，**就是不触发** |

而实测唯一有效的，是最朴素的这一条：

```sh
hdparm -y /dev/sdb      # SCSI START STOP UNIT，立刻停转
```

**关键区别**：`-y` 走 SCSI `START STOP UNIT`，桥接普遍支持；
`-S` 走 ATA `IDLE`，没有 SCSI 映射，桥接**不转发**。

> **最大的坑是 `hdparm -S` 返回 0。**
> 它不报错、不警告，你会以为设置成功了。只有把时间缩短到 2 分钟实测，才会发现盘根本没睡。

### 正确的排查顺序

**第一步：体检**

```bash
sh hdd_sleep_diag.sh              # 自动检测所有 sd*，采样 60 秒
sh hdd_sleep_diag.sh sdb 120      # 指定盘，采样 120 秒
```

六节输出：设备与挂载 → `hdparm` 透传测试 → SMB 现状 → 谁在写盘 →
内核侧 I/O → 强制入睡并观察多久被吵醒。

**第二步：验证（这一步不能省）**

```bash
sh verify_sleep.sh        # 临时设 2 分钟，等它自己睡，测完恢复 120 分钟
```

它做的事：设 `-S 24`（2 分钟）→ 每 15 秒 `hdparm -C` 查状态 → 最后恢复。

- 看到 `standby` → `hdparm -S` 这条路通，可以直接用它（更简洁，无需常驻进程）
- 一直 `active/idle` 而盘确实空闲 → **假成功，转第三步**

`hdparm -C` 是 CHECK POWER MODE，只是问"睡了没"，**不会把盘吵醒**。

**第三步：用 cron 实现**

```bash
sh cron_sleep.sh          # 120 分钟
sh cron_sleep.sh 240      # 4 小时
sh cron_sleep.sh 0        # 卸载
```

它会：
1. 先验证 `hdparm -y` 此刻是否有效（无效则直接退出，不白折腾）
2. 装 `/usr/bin/disk-sleep-check.sh`：读 `/proc/diskstats` 判断有无 I/O，
   连续空闲达阈值就 `hdparm -y`
3. 注册 cron 每 5 分钟跑一次，并确保 `crond` 开机自启
4. **自测**：把状态时间戳伪造成"很久以前"，手动跑一次，几秒内验证会不会触发
5. 停掉 `hd-idle`，避免两套机制互相干扰

### 为什么不用 hd-idle

`hd-idle` 本身没问题，它发的也是 spindown-now。但它：

- 配置里 `option 'disk'` **写死设备名**（`sdb`），重启后盘变成 `sdc` 就失效了，而且不报错
- 在这台机器上实测：进程在跑、参数正确（`-d -i 0 -a sdb -i 120`）、盘完全空闲，
  150 秒后仍不触发，无法信任

自己用 cron 实现，逻辑只有十几行，但**每一点都可见可调**：

```sh
# 核心逻辑，就这么点
cur=$(awk -v d="$DEV" '$3==d {print $4+$8}' /proc/diskstats)
if [ "$cur" != "$last_io" ]; then 记录时间; 退出; fi
if [ 空闲 >= 阈值 ]; then hdparm -y /dev/$DEV; fi
```

**每次运行都按型号重新找盘**，设备名变了自动适应 —— 这是 hd-idle 的 uci 配置做不到的。

### 两个实现细节（容易踩）

**① I/O 计数不要用扇区数。**
`/proc/diskstats` 的 `$6`/`$10` 是扇区数，2.8TB 盘会超过 awk 的安全整数范围，
`print` 可能输出科学计数法，导致字符串比较失效。
用 `$4`/`$8`（读写**次数**），数值小得多，而且对小 I/O 更敏感。

**② 状态文件放 `/tmp`。**
重启清空 → 重新计时，符合"重启后不该立刻睡"的预期。
如果放持久目录，重启后会拿旧的空闲时间直接判睡，反而不好。

### 时间设多长

**按"多久用一次"定，不要贪短。**

- 每次访问的代价是**一次启停**（唤醒 3~10 秒，机械磨损）
- 经验分界线：**启停超过 20 次/天**才开始明显折寿
- 偶尔用 → 2~4 小时；天天频繁用 → 设 `0` 不管，一直转
- 设 5~10 分钟几乎必然是错的：会被 SMB 浏览、缩略图、媒体库扫描反复吵醒

cron 方案的精度是**检查间隔**（默认 5 分钟），设 120 分钟实际在 120~125 分钟内入睡。

### 一个反直觉的结论

**SMART 的 `Power_On_Hours` 在 standby 状态下通常不走。**

所以一块"通电一年"的盘只显示几百小时，是正常的 ——
算一下比例：`734 / 8760 = 8.4%`，说明它 **91.6% 的时间在睡**，**不是盘很新**。

先看这个比例，再决定要不要干预。别看到小时数低就说"盘是新的"。

### 其它实测记录

- `hdparm -S` 的值**读不回来**：没有读取选项，`-I` 只报能力不报当前值
- USB 盒子常不上报电源状态（`hdparm -C` 返回空或 `unknown`），
  此时只能靠听停转 / 摸温度 / 看功率计（典型 5.5W → 1.8W）
- `hdparm -I` 能读到完整 IDENTIFY（型号、序列号、固件版本），
  说明**桥接支持 ATA PASS-THROUGH**——但这**不代表**它支持 `IDLE` 命令，
  两者是不同的 opcode，别混淆

## 让别的 AI 用这个工具

压缩这件事最容易被 AI 理解错：它默认会把**所有文件打成一个总包**（`zip -r`），
而这里要的是**每个文件各自一个包**。所以开口时必须说清是哪一种。

### 第一档：它能下载文件（最省事，优先用这个）

> 我有个现成的压缩工具，别自己写。先下载到本地：
>
> ```
> curl -fsSL -o zip_each.py https://raw.githubusercontent.com/xh22th0324-ux/ai-brain/main/tools/zip_each.py
> ```
>
> 这是公开仓库，**不需要任何凭据**。用法：
>
> ```
> python3 zip_each.py <目标目录> --dry-run   # 先给我看计划，别直接压
> python3 zip_each.py <目标目录>             # 我确认后再跑
> ```
>
> 它的作用是：把目标目录**第一层**的每个文件**各自**压成一个独立压缩包
> （`a.txt → a.zip`、`b.mp4 → b.zip`），**原文件一个字节都不改**；
> 已经压过且源文件没变的会自动跳过。
> 详细行为见同目录 `README.md`。

### 第二档：它是本地 CLI（Codex CLI / Gemini CLI / Cursor 等）

> 执行 `git clone --depth 1 https://github.com/xh22th0324-ux/ai-brain`，
> 脚本在 `tools/zip_each.py`，`tools/README.md` 是它的说明。公开仓库，无需凭据。
> 只读，不要往仓库里推任何东西。

### 第三档：它拿不到文件，只能按描述自己写

这时才让它写，但要给足约束 —— 少一条就容易出一个"看起来能用、实际会丢数据"的版本：

> 写一个脚本实现「把目录下每个文件各自压成一个独立包」，**必须满足**：
>
> 1. 只处理目录**第一层**，不递归子目录
> 2. 命名用「原文件名去掉扩展名 + `.zip`」（`a.txt → a.zip`）；
>    两个文件去掉扩展名后重名时改成追加形式（`photo.jpg → photo.jpg.zip`），别互相覆盖
> 3. **原文件绝对不删、不改、不移动**
> 4. **目标包已存在且不比源文件旧就跳过**；包比源文件旧说明源改过，要重压。
>    时间比较留 2 秒容差（FAT/exFAT 的精度就是 2 秒）
> 5. 先写 `<包名>.part`，写完再原子改名，中断时不能留下"看起来完整"的坏包
> 6. 中文文件名要正常，路径里有空格要能处理
> 7. 已经压过的源文件（`.zip/.rar/.7z`）默认跳过，否则会出现 `a.zip.zip`
>
> 写完先 `--dry-run` 给我看计划，我确认后再跑。

### 别这么说（实测会被理解错）

| 说法 | 它通常会怎么做 | 问题 |
|---|---|---|
| "帮我压缩一下这些文件" | `zip -r all.zip .` 打成一个总包 | 完全不是要的东西 |
| "每个文件单独压" （不说清落点） | 压成 `a.txt.zip`，多一层扩展名 | 你要的是 `a.zip` |
| 不说目标目录 | 按它自己的 cwd 压 | 压错目录，还可能压到仓库里 |
| "顺便把源文件删掉" | 删了 | 这里不该有删除动作，压缩是只读的 |

**一句话记法**：说「每个文件**各自一个包**」，并强调「**原文件不动**」。
